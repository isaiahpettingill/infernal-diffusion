# Godot desktop extension

Copy `addons/infernal_diffusion` into a Godot 4.6+ project, including the binaries
produced by `tools/build_gdextension.py`. Use a Godot editor matching the
packaged extension architecture. `godot/extension` is the Rust GDExtension shim.

For immediate gameplay use, generate in memory. This returns the Rust-generated
monster as nested Godot dictionaries/arrays and each atlas as raw RGBA bytes;
the generator does not encode or decode protobuf on this path.

For an NPC that speaks its own monster prompts, call
`suggest_prompt_async(seed, difficulty)` with difficulty 1, 2, or 3. The
result from `poll_result()` has `prompt`, `difficulty`, and `monster_seed`.
Speak `prompt`, then pass that exact string and `monster_seed` to
`generate_in_memory_async`. `suggest_arena_prompt_async(run_seed, round)`
uses one-based rounds; rounds 1–3 are difficulty 1, 4–6 are 2, and 7 onward
are 3. See `godot/examples/throne_summoner.gd` for a complete wave director.

```gdscript
var monsters := InfernalDiffusion.new()
var job := monsters.generate_in_memory_async("giant spider that shoots fire", 42)

func _process(_delta: float) -> void:
	var result := monsters.poll_result()
	if result.is_empty() or result.job_id != job:
		return
	if !result.ok:
		push_error(result.error)
		return
	var root: Dictionary = result.packages.back() # Child packages precede the root.
	var hp: int = root.monster.gameplay.health
	var image := InfernalDiffusion.image_from_rgba(root.sprites)
	var texture := ImageTexture.create_from_image(image)
	print(root.monster.display_name, " HP: ", hp, " texture: ", texture)
```

The result also contains `emission` and, where applicable, `projectiles` atlases.
Mounted or spawning monsters include child packages in `result.packages`; use
each package's `path` together with `mount` or `spawn.package_path` metadata.
Up to four in-memory monsters can be retained per generator. Call
`save_in_memory_async(job, "user://monsters/spider")` to write protobuf and
PNG assets on the worker thread, and `release_in_memory(job)` when the native
copy is no longer needed. Keep the returned Godot dictionaries and byte arrays
for gameplay after release.

Direct package generation is also available:

```gdscript
var monsters := InfernalDiffusion.new()
var job := monsters.generate_async("giant spider that shoots fire", 42, "user://monsters/spider")

func _process(_delta: float) -> void:
	var result := monsters.poll_result()
	if !result.is_empty() and result.job_id == job:
		if result.ok:
			print("Package: ", result.package_dir, " CPU backend: ", result.backend)
		else:
			push_error(result.error)
```

The call queues at most one waiting generation per `InfernalGenerator` instance.
Generation runs on a dedicated worker; `poll_result()` never waits. A queue-full
request returns `-1`. Create one `InfernalDiffusion` instance for the game to keep
CPU work bounded. A saved result directory contains `monster.pb` and `sprites.png`.

For saved packages, `monster_pb.gd` is generated by the bundled
[Godobuf](https://github.com/oniksan/godobuf) 0.7.0 compiler (BSD-3-Clause).
Godobuf 0.7.0 targets Godot 4.6. The generated reader works with the
package-free `monster_godobuf.proto`, which has exactly the same wire field
numbers as `proto/monster.proto`. Godobuf cannot parse `package` declarations.

```gdscript
const MonsterPb = preload("res://addons/infernal_diffusion/monster_pb.gd")
var saved := MonsterPb.InfernalMonster.new()
var bytes := FileAccess.get_file_as_bytes("user://monsters/spider/monster.pb")
assert(saved.from_bytes(bytes) == MonsterPb.PB_ERR.NO_ERRORS)
print(saved.get_display_name(), " ", saved.get_gameplay().get_health())
```

After changing the canonical schema, run
`python tools/regenerate_godobuf.py --godot /path/to/Godot-4.6`.

The x64 generator is one baseline-compatible library. It selects its v2 or
v3 rasterizer at runtime when the CPU and OS support the required instructions;
older CPUs use the baseline rasterizer. The `backend` field in `poll_result()`
reports the selected kernel.

Generation runs on a worker thread. On machines with at least four logical
cores, sprite rendering uses two additional workers; smaller machines render
on the generation thread. This leaves capacity for the game loop. The runtime
does not need OpenGL or a GPU context to generate sprites. For CPU comparisons,
set `INFERNAL_CPU_KERNEL` to `x64`, `x64_v2`, or `x64_v3` (the override cannot
enable instructions the host lacks), then run `python tools/bench_generate.py
path/to/infernal_diffusion.dll --prompt "wolf" --runs 3`.

For an editor import, run the build script for your host target, then copy the
`addons/infernal_diffusion` directory into your project. Exported builds use the
manifest's dependency list to place the generator libraries beside the executable
(in `Contents/Frameworks` on macOS).

The `Godot desktop binaries` GitHub Actions workflow builds downloadable addon
artifacts for Windows, Linux, and macOS across x86_32, x86_64, and arm64 where
supported. On x86_64 it builds one library with baseline, v2, and v3 kernels.
