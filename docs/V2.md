# Infernal Diffusion V2

V2 is an opt-in procedural recipe refinement profile, not a trained diffusion
model. V1 remains the default. The same CPU anatomy, articulated motion and
palette sprite-baking foundation runs natively and in the browser.

## What changes

- Species-conditioned coherent rest proportions and depth, avoiding independent
  joint jitter. Shared body-family refinement covers the existing recipe roster;
  frogs, mermaids and trees have dedicated silhouette landmarks.
- Tapered organic connectors, shaped muscle/body volumes, patterned surfaces and
  deterministic coordinated color variation. Natural animal palettes stay close
  to their material family; fantasy creatures admit broader color variation.
- Bounded aimed, burst, fan, acid-spray and fire-spray attack recipes. Every actual
  projectile emission has a matching animation event. The engine chooses targets,
  applies damage and interprets the declared pattern.
- Friendly lure variants requested with `friendly`, `cute`, `smiling` or `lure`:
  harmless visual lures, a separate reveal telegraph, and hostile attacks. Explicit
  attack elements/deliveries are retained; unspecified lure attacks default to a
  bounded spray. A friendly frog is still allowed to be an ordinary frog.

These are refinements of existing recipes rather than a claim that every species
has a uniquely hand-sculpted mesh. Mounted composites retain their established
anatomical proportions; their parts receive V2 visual treatment.

## Engine contract

The optional `monster.v2_profile` extension contains versioned categories,
capabilities, modifiers, attack-pattern summaries and an optional lure descriptor.
It is absent from V1 serialization. Attack summaries refer to the full `attacks`
array; clip references point to actual baked animations. `TARGET_ACTOR` is selected
by the engine, not by the generator.

The lure descriptor proposes `TARGET_WITHIN_RADIUS`, a distance in generator
length units, a harmless looping lure clip, a one-shot reveal clip and the attack
ID to select afterward. Consumers rescale that radius with their world units and
own visibility checks, proximity tests, aggression and state transitions. The
library does not run NPC AI or move actors down scripted paths. See the profile
API guide for lure rearming behavior.

Keep using returned atlas dimensions, columns, anchors and per-frame timings.
More clips can make atlases larger; do not assume fixed offsets or 128px frames.
Review creatures at their actual gameplay pixel scale, not just an enlarged image.

## Determinism and compatibility

V2 has its own `profile.v2@1` recipe identity and preserves the supplied seed.
Save the generated package or its generator/recipe version as well as the seed;
future recipe revisions intentionally change generated identities. Existing V1
entry points and simple-parser builds remain supported. New profile APIs reject
unknown versions instead of silently falling back.

Water navigation is an intentional shared correction in both V1 and V2, versioned
as `motion.aquatic_navigation@1`. Terrestrial V1 golden artifacts remain unchanged.
See [aquatic animation](aquatic-animation.md) and [profile APIs](generation-profiles.md).

## Reproduce the visual catalog

```sh
cargo run --release --no-default-features --example profile_catalog -- output/profile-catalog
cargo test --release --no-default-features
cargo test --release
```

The catalog writes actual atlas PNGs, metadata JSON, emission maps and preview PNGs
for twelve recipe subjects in both profiles. It uses seed 42. `export_intermediate`
is available for inspecting exact mesh triangles, for example:

```sh
cargo run --release --no-default-features --example export_intermediate -- \
  "friendly mermaid that sprays acid" 42 output/mesh v2_lure --profile v2
python tools/profile_evidence.py output/profile-catalog output/profile-comparison.png
```
