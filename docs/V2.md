# Infernal Diffusion V2

V2 is an opt-in procedural recipe refinement profile, not a trained diffusion
model. V1 remains the default. The same CPU anatomy, articulated motion and
palette sprite-baking foundation runs natively and in the browser.

## What changes

- Species-conditioned coherent rest proportions and depth, avoiding independent
  joint jitter. Shared body-family refinement covers the existing recipe roster;
  frogs, mermaids and trees have dedicated silhouette landmarks.
- Tapered organic connectors, shaped muscle/body volumes, patterned surfaces and
  deterministic coordinated color variation. Natural animal palettes stay close
  to their material family; fantasy creatures admit broader color variation.
- Bounded aimed, burst, fan, acid-spray and fire-spray attack recipes. Every actual
  projectile emission has a matching animation event. The engine chooses targets,
  applies damage and interprets the declared pattern.
- Friendly lure variants requested with `friendly`, `cute`, `smiling` or `lure`:
  harmless visual lures, a separate reveal telegraph, and hostile attacks. Explicit
  attack elements/deliveries are retained; unspecified lure attacks use a bounded
  spray or the creature's dedicated tree-smash/merfolk-lunge capability. A friendly frog is still allowed to be an ordinary frog.

These are refinements of existing recipes rather than a claim that every species
has a uniquely hand-sculpted mesh. Mounted composites retain their established
anatomical proportions; their parts receive V2 visual treatment.

## Engine contract

The optional `monster.v2_profile` extension contains versioned categories,
capabilities, modifiers, attack-pattern summaries, posed attack-origin tracks,
explicit hybrid provenance and optional lure/spectral descriptors.
It is absent from V1 serialization. Attack summaries refer to the full `attacks`
array; clip references point to actual baked animations. `TARGET_ACTOR` is selected
by the engine, not by the generator.

The lure descriptor proposes `TARGET_WITHIN_RADIUS`, a distance in generator
length units, a harmless looping lure clip, a one-shot reveal clip and the attack
ID to select afterward. Consumers rescale that radius with their world units and
own visibility checks, proximity tests, aggression and state transitions. The
library does not run NPC AI or move actors down scripted paths. See the profile
API guide for lure rearming behavior.

Keep using returned atlas dimensions, columns, anchors and per-frame timings.
More clips can make atlases larger; do not assume fixed offsets or 128px frames.
Review creatures at their actual gameplay pixel scale, not just an enlarged image.

## Determinism and compatibility

V2 has its own `profile.v2@2` recipe identity and preserves the supplied seed.
Save the generated package or its generator/recipe version as well as the seed;
future recipe revisions intentionally change generated identities. Existing V1
entry points and simple-parser builds remain supported. New profile APIs reject
unknown versions instead of silently falling back.

Water navigation is an intentional shared correction in both V1 and V2, versioned
as `motion.aquatic_navigation@1`. Terrestrial V1 golden artifacts remain unchanged.
See [aquatic animation](aquatic-animation.md) and [profile APIs](generation-profiles.md).

## Reproduce the visual catalog

```sh
cargo run --release --no-default-features --example profile_catalog -- output/profile-catalog
cargo test --release --no-default-features
cargo test --release
```

The catalog writes actual atlas PNGs, metadata JSON, emission maps and preview PNGs
for sixteen recipe subjects in both profiles. It uses seed 42, except the ordinary
mermaid baseline uses seed 0. `export_intermediate`
is available for inspecting exact mesh triangles, for example:

```sh
cargo run --release --no-default-features --example export_intermediate -- \
  "friendly mermaid that sprays acid" 42 output/mesh v2_lure --profile v2
python tools/profile_evidence.py output/profile-catalog output/profile-comparison.png
```

## Portable V1 regression check

CI builds the untouched pre-V2 commit `6f0c9b31eabfdc9e1b593cf1c3621f75d63dd9f3`
and the candidate with the same compiler on the same runner, then compares every
PNG and protobuf byte for eleven terrestrial specimens. This includes the full
serialized animation, combat and recipe metadata, not only appearance. There is
no image tolerance and no regenerated expected output. Aquatic corrections are
intentionally outside this terrestrial comparison.

The original nine frozen raw-pixel/protobuf hashes remain in the repository as an
explicitly runnable diagnostic (`cargo test --release --no-default-features
terrestrial_v1_matches_pre_v2_golden_bytes -- --ignored`). The first hosted run
revealed a beetle raster hash difference despite identical Rust compiler versions;
local scalar/SIMD dispatch choices did not reproduce it. The precise cross-host
math cause is not established. The portable report additionally records whether
the untouched baseline itself matches the original host's PNG/protobuf hashes,
so baseline platform drift is distinguishable from a V2-introduced regression.

## Humanoid refinement and bounded "AI mistakes"

V2 uses shallow species-specific faces instead of the legacy pointed humanoid
head: jaws, eye patches and continuous mouths for humans and merfolk; broad orc
jaws and tusks; and a distinct trooper visor/helmet. Merfolk hair uses swept tapered
locks. Humanoid hybrids retain their recognizable native body and appendages;
explicitly animal-headed creatures keep their animal face. V1 facial geometry is
unchanged. Recipe revision `profile.v2@2` separates these outputs from the first
V2 preview; descriptor schema `profile_version: 1` is unchanged.

A separate deterministic topology stream occasionally adds a second arm pair or
extra tail. Explicit arm/tail counts suppress random changes in that scope, and
mounted creatures are excluded. These are connected generated rigs, not arbitrary
floating accessories. Modifier tags `FOUR_ARMED`, `EXTRA_TAIL` and `MUTANT_UNSTABLE`
identify the variation. Four-arm mutants fold their extra arms close to the body
outside attacks, then unfold them on attack; this changes the visible silhouette
without inventing runtime nodes. `FOLDED_EXTRA_ARMS_UNFOLD` describes that effect.

Merfolk gain full-body lunges and tail-whip attacks. Trees with two or more arms
gain a bilateral smash: connected arms grow by at most 1.8×, raise, then strike
together. `BOUNDED_ARM_EXTENSION_MAX_1_8` and its matching clip event explicitly
permit this limited animation deformation; other rig-length checks still apply.
`AWKWARD_COORDINATION` mutants have longer windup/recovery and small connected-arm
phase lag, but keep locomotion and all attack emissions. This is a bounded gameplay
drawback, not an unusable animation or an engine AI implementation. Engines still
choose attacks and targets using the supplied preferences and attack recipes.

Generate the seed-variety/attack catalog with:

```sh
cargo run --release --no-default-features --example v2_variants -- output/v2-variants
```

## Explicit composition and spectral creatures

[Hybrid recipes](hybrid-recipes.md) independently select an upper body, lower
body, head, lower leg count and upper arm count. Native prompts and a strict
versioned JSON schema share the same assembly logic. Six-legged centaurs have
six lower-body legs plus their upper arms; spider-centaurs, fish-headed humanoids,
trooper/mermaid combinations and walking trees preserve each selected part's
identity and lower-body propulsion. Unsupported combinations fail validation.

[Spectral rules](spectral-contract.md) separate appearance, solid collision and
damage. Shades are opaque ink silhouettes and replace the source creature's
weapon/bite offense with whole-body tendril lash/thrust attacks. Head, torso and
limbs unwind into three connected strands, then replay the exact frames in reverse
to reform. Growth is bounded at 1.8×; recovery has no second hit. Windup, phase
intervals and active contact are explicit. No original gun attack or unused gun frames are
retained. FIRE/WATER damage takes precedence over projectile pass-through.
Ghosts are translucent and require magic; ordinary ghouls have readable spectral
attacks but no blanket damage immunity. The engine applies these rules.

Skeletons use actual skull cavities, rib cages, pelvis and long-bone meshes plus
bounded seeded bone spurs; the functional rig remains connected. All these visual
changes are V2-only. See the enumerated [humanoid face coverage](../assets/v2/humanoid_face_coverage.json)
for refined humanlike families and intentional animal-headed exceptions.

[Attack-origin tracks](attack-origin-tracks.md) contain exact posed, projected
contact locations for each baked frame and view. They keep growing arms and
tendrils aligned with declared active windows without requiring the consumer to
reconstruct the generator's rig. This is output data, not an engine controller.

```sh
cargo run --release --no-default-features --example v2_composites -- output/v2-composites
python tools/v2_composite_evidence.py output/v2-composites output/composite-review
python tools/v2_variant_evidence.py output/v2-variants output/variant-review
```
